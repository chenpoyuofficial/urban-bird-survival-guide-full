This is a Node.js + Express + Prisma (PostgreSQL) REST API, driven via
`curl`/HTTP — there's no GUI. The agent path is
`.claude/skills/run-server/smoke.sh`, which launches the server in the
background, waits for it to be healthy (server *and* database), then
drives one full request flow (register → post → comment → cleanup)
through the real HTTP API.

All paths below are relative to `server/`.

## Prerequisites

- Node.js (this was verified against the Node already on PATH in this
  environment — no version pin needed beyond what `package.json` expects).
- A running local PostgreSQL instance, with two databases already created:
  `urban_bird_survival_guide` (dev) and `urban_bird_survival_guide_test`
  (test — used by `npm test`, not by this skill).
- `npm install` already run (`node_modules/` present).

This environment is Windows + Git Bash, not a Linux container — there's
no `apt-get`, and no `lsof` (see Gotchas for the Windows-specific bits
that follow from that).

## Setup

Copy `.env.example` to `.env` and fill in real values:

```bash
cp .env.example .env
```

| Variable | Required | Default | Notes |
|---|---|---|---|
| `PORT` | No | `5000` | |
| `DATABASE_URL` | Yes | — | `postgresql://<user>:<password>@localhost:5432/urban_bird_survival_guide` |
| `JWT_SECRET` | Yes | — | any random string; generate with `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` |
| `CLIENT_URL` | No | `http://localhost:5173` | for CORS |

Boards are seeded data, not created through the API — run once against
a fresh database:

```bash
npm run seed
# -> Boards seeded: 育雛資訊、生存指南、日常分享、覓食情報
```

## Build

No separate build step (plain JS, no bundler). `prisma generate` runs
implicitly via `prisma migrate dev`/`deploy`, and already ran when the
migrations in `prisma/migrations/` were created — nothing to do on a
normal clone as long as `node_modules/.prisma/client` exists (it's
regenerated by `npm install`'s postinstall). If it's ever missing:

```bash
npx prisma generate
```

## Run (agent path)

```bash
bash .claude/skills/run-server/smoke.sh
```

This backgrounds `npm run dev`, polls `GET /api/health` until both the
server and the database are up, then runs a real flow through the live
API: list boards, register a user, create a post, hit the recommended-posts
endpoint, add a comment, then delete the comment/post/user it created.
Prints each step's result. Exit code is non-zero if the server never
became healthy. Server log lands at `/tmp/server.log`; the server is
stopped again before the script exits.

For one-off manual poking instead of the full flow, launch the same way
and hit endpoints directly:

```bash
npm run dev > /tmp/server.log 2>&1 &
SERVER_PID=$!
for i in $(seq 1 30); do curl -sf http://localhost:5000/api/health > /dev/null && break; sleep 1; done
curl http://localhost:5000/api/boards
```

Chinese (CJK) text in request/response bodies — don't debug it via
`curl` output in Git Bash (see Gotchas). Use `node -e` with `fetch()`
instead when you need to actually read Chinese content.

### Stopping the server manually

```bash
taskkill //F //T //PID "$SERVER_PID" 2>/dev/null || true
netstat -ano | grep ":5000.*LISTENING" | awk '{print $5}' | sort -u | xargs -r -I{} taskkill //F //PID {}
```

## Gotchas

- **Killing the port's current listener isn't enough to stop the server.**
  `npm run dev` runs `nodemon`, which is a 3-level process tree
  (`npm` → `nodemon` → `node`). If you kill only the `node` process
  currently listening on the port (e.g. via a stray `netstat`+`taskkill`
  one-liner), `nodemon` treats that as a crash and immediately respawns
  a *new* `node` process on the same port — the port stays occupied
  under a different PID. Kill the whole tree with
  `taskkill //F //T //PID "$SERVER_PID"` first (where `$SERVER_PID` is
  the PID captured right after backgrounding `npm run dev`), *then*
  sweep the port as a fallback. `smoke.sh` does both.
- **No `lsof` in Git Bash on Windows.** Use
  `netstat -ano | grep ":<port>.*LISTENING" | awk '{print $5}'` to find
  the PID on a port, and `taskkill //F //PID <pid>` (or `//F //T //PID`
  for the whole tree) instead of `kill`/`kill -9`.
- **`curl` output in Git Bash mangles CJK/UTF-8 text** (garbled bytes,
  not real corruption) — this cost time to debug once already this
  project. If a response body has Chinese text and looks corrupted in
  `curl`'s terminal output, verify with `node -e "fetch(...).then(r=>r.json()).then(d=>console.log(JSON.stringify(d)))"`
  instead before assuming there's a real encoding bug.
- **Prisma 7 breaking changes** (this project pins `prisma@^7.9.1`):
  `datasource.url` no longer lives in `schema.prisma` — it's in
  `prisma.config.js` (`datasource: { url: env('DATABASE_URL') }`).
  `PrismaClient` requires an explicit driver adapter
  (`server/lib/prisma.js` does `new PrismaPg({ connectionString })`).
  `@prisma/client`'s generated CJS export means
  `import { PrismaClient } from '@prisma/client'` throws a
  `SyntaxError: Named export 'PrismaClient' not found` — always import
  as `import pkg from '@prisma/client'; const { PrismaClient } = pkg`.
- **Health check checks the database, not just the process.**
  `GET /api/health` runs `SELECT 1` through Prisma and returns
  `503 { error: { code: 'DATABASE_UNAVAILABLE' } }` if the DB is
  unreachable — a `200` genuinely means both the server and Postgres
  are up, not just that Express is listening.

## Troubleshooting

- **`SyntaxError: Named export 'PrismaClient' not found`**: see the
  Prisma 7 gotcha above — use the default-import-then-destructure form.
- **`Error: SASL: SCRAM-SERVER-FIRST-MESSAGE: client password must be a string`**
  from a one-off `node -e` script that touches `lib/prisma.js`: means
  `DATABASE_URL` wasn't set in that process's environment — the script
  didn't `import('dotenv/config')` before importing `lib/prisma.js`.
- **`node_modules/.prisma/client` missing / stale after a schema
  change**: run `npx prisma generate` explicitly — it doesn't always
  happen automatically as part of `migrate dev`/`deploy`.
- **Server port still occupied after you thought you killed it**: see
  the nodemon-respawn gotcha above.
